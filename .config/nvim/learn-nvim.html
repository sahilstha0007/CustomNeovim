Part 0 · Orientation

00The one big idea normal

Neovim is modal: the same keys do different things depending on the mode you're in. Most editors are one big text box; nvim is four small ones, and you switch between them on purpose. This is why it feels alien for a week and fast forever after.

  • Normal — your home base. Every key is a command: j moves down, d deletes, p pastes. You live here ~70% of the time.
  • Insert — actual typing. Enter it briefly, type, leave. Escaping back to Normal is the habit that makes vim fast.
  • Visual — selecting text. Like Normal, but keys affect the selection instead of the cursor.
  • Command — the : line. Save, quit, search-replace, run ex commands.
Rule one: whenever you finish doing something, press Esc and get back to Normal. Your config even makes Esc clear search highlighting for you.

Movement is the first skill. Notice your relative line numbers — they're there so you can count jumps with your eyes.

W B ESame, but by whitespace-separated words (skips punctuation).

gg GTop of file / bottom of file. Add a count: 12G or 42gg.

Part I · Modes

02Normal mode: editing normal

The grammar of vim editing: verb + noun. d (delete), c (change = delete + insert), y (yank = copy) — followed by a motion or text object.

x XDelete char under / before the cursor.
dd yy p PDelete line, copy line, paste after cursor, paste before. 3dd cuts three lines.
dw d$ d0Delete word, to end of line, to start of line.
u C-rUndo / redo. Your undo survives restarts (undofile is on).
.Repeat the last change. dd then . . . deletes line after line. The most powerful key in vim.
rx ~Replace one char with x; flip case of a char.
JJoin the next line onto this one.
cw ciwChange a word — deletes it and drops you into Insert. The fastest way to retype a word.
gu gU g~Lowercase / uppercase / flip case of a motion or line: guu, gU$, gUiw.
=Re-indent: == this line, gg=G the whole file.
> <Indent / outdent. In visual mode it stays on the selection (your config).
# the verb-noun pattern in one line
d  w     → delete  word
c  i  "  → change  inside  quotes
y  i  }  → yank    inside  braces
gU i w    → uppercase inner word
counts multiply everything:  3ciw  = change the next 3 words
your config · lua/options.lua + lua/keymaps.lua
vim.opt.undofile = true            -- undo survives restarts
vim.opt.clipboard = 'unnamedplus'  -- yank/paste use the OS clipboard

-- < and > in visual keep the selection so you can repeat
vim.keymap.set('v', '<', '<gv')
vim.keymap.set('v', '>', '>gv')
Hardtime is watching: your setup runs hardtime.nvim to break the dd/x mashing habit. It intentionally makes those slower until you start using motions + counts — the exact skills these lessons teach.

04Visual mode: selecting visual

Visual is Normal with a selection. Highlight, then act — delete, change, yank, or re-indent.

vCharacter-wise select. Move with any motion: vw, vfx, v%.
VLine-wise select — the one you'll use most for moving blocks.
C-vBlock select (columns). Select a column and type I to edit every line at once.
d c y u ~Delete, change, yank, lowercase, swap-case the selection.
H L J KYour config: move the selected block left/right/down/up (mini.move). Select lines with V, then J/K to reorder.
gvRe-select the last selection. Great for "I yanked the wrong bit".
oFlip the cursor to the other end of the selection (handy when you overshoot).

Block editing (the superpower)

  1. C-v, move down to cover several lines.
  2. I (capital i), type your prefix, Esc — the text is inserted on every line at once.
  3. Or select a column and press x/c to delete/replace a column across lines.

require('mini.move').setup { mappings = { left = 'H', right = 'L', down = 'J', up = 'K' } }

-- better indenting: < and > keep the selection (keymaps.lua)
vim.keymap.set('v', '<', '<gv')

05Command mode: : command

Press : and you get a full command line. This is where file ops, search-replace, and hundreds of ex-commands live.

:w :q :wqSave / quit / save-and-quit. :q! quits without saving.
:e file :e!Open a file by name / reload from disk.
:w new.txtSave the buffer under a new name.
:%s/old/new/gReplace every old with new in the file. g = all on each line.
:%s/foo/bar/gcSame, but confirm each one — y/n/q as you go.
:10,20dRanges: delete lines 10–20. :.d current line, :1,$ whole file.
:!cmdRun a shell command: :!node script.js. :r!cmd reads its output into the buffer.
q: q/Open the command history / search history in a window you can edit.
Live preview: your config sets inccommand = 'split', so :s/ shows the replacement live as you type. Type the pattern, watch the file change.

12Search & replace command

From simple find-replace to regex: the full :s toolkit, plus your Spacesr project-wide replace UI.

CommandWhat it does
:s/old/new/Replace on the current line only, first match.
:%s/old/new/gReplace in the whole file, all matches per line.
:%s/old/new/gcSame, with confirmation for each match.
:%s/old/new/giCase-insensitive (overrides smartcase for this command).
:%s/old/new/gICase-sensitive.
:3,12s/x/y/gOnly lines 3–12. '<,'> = the visual selection.
:g/foo/dDelete every line containing foo. :g!/foo/d keeps only them.

Regex essentials (vimgrep style)

  • . any char · ^ line start · $ line end · \</\> word boundaries.
  • [abc] one of · [^abc] not one of · \d digit · \s whitespace.
  • * zero or more · \+ one or more · \? optional · \(...\) capture.
  • \v (very magic) makes the pattern read like most regex engines — :s/\vfoo(.+)bar/.../.
Project-wide replace: Spacesr opens grug-far — type, preview every match, replace across files. It pre-fills the file-type filter from your current buffer.

13Registers: the clipboard you control normal

Every delete and yank lands in a register — think of them as named clipboards. This unlocks "yank two things, paste both" and turns your system clipboard into a vim citizen.

RegisterContents
" (unnamed)Last delete/yank. That's what p pastes.
0–9Last 10 yanks (0 = most recent). "0p pastes your last yank even after a delete.
-Small delete (a single char).
a–zNamed registers you control: "ayy yank line into a, "ap paste it.
+ / *System clipboard. Because your config sets clipboard=unnamedplus, plain y/p already touch it.
_Black hole: "_dd deletes without clobbering your clipboard.
%Current file name. "%p pastes it — handy in a script.
Spaces"Your config: open the register picker — see everything, paste with Enter.
SpacesyYour config: yank history — browse every yank/delete from this session and across restarts (yanky).
:reg :reg aShow all registers / just register a.
"aPPaste register a before the cursor. Uppercase A appends to a register: "Ay.
Clipboard is on: clipboard = 'unnamedplus' means y in nvim and Ctrl-C in your browser share the same buffer. Paste from the web with p directly.

15Macros: record any edit normal

A macro records keystrokes into a register, then replays them — the ultimate fix for "I've done this 40 times".

qaStart recording into register a.
qStop recording.
@aReplay register a.
@@Replay the last macro again.
100@aReplay 100 times — it stops at the end of the file, so "just run out of matches" is fine.

Recipe: repeat on every line

  1. Go to the first line. qa — start recording.
  2. Do your edit (change word, delete, reorder…).
  3. j — move to the next line (so replay lands right).
  4. q — stop. Now @a on every line, or 100@a.
Fix a macro mid-flight: if it goes wrong, u, then edit the recorded text in a buffer via "ap, fix it, "ay$ to save it back, replay.

24Plugins & your config normal

Everything in this setup is a lazy.nvim spec: one file per plugin under lua/plugins/<category>/, imported by lua/lazy-init.lua. This is the config you'll be editing — know its shape.

:LazyOpen the plugin manager UI — status, updates, clean.
SpacelYour config: pick a lazy action from a menu — sync, install, update, clean, check, restore, profile, health, log, debug.
:Lazy updateUpdate all plugins.
:Lazy cleanRemove plugins whose specs you deleted.
:Lazy logShow the update log.

Adding a plugin (the 3-step ritual)

  1. Create lua/plugins/<category>/<name>.lua with a spec table.
  2. Add { import = 'plugins.<category>.<name>' } to the spec list in lua/lazy-init.lua.
  3. Restart nvim. Removing one? Delete the file, the import line, then run :Lazy clean.
your config · boot order in init.lua + layout
vim.g.mapleader = ' '        -- 1. leader before anything
require 'globals'       -- 2. mise shims, diagnostics, netrw off
require 'options'       -- 3. every vim.opt
require 'keymaps'       -- 4. custom keys

-- layout:  lua/plugins/<cat>/<name>.lua  +  lsp/<server>.lua  +  docs/
Your config has docs. docs/ explains every plugin, LSP server, and keymap. When you forget why something exists, start there.
